### A4. ⚪ 낮음 (모아서 처리)

- 결과 버튼 잔상: 취소·실패 후 이전 실행의 "용어집 저장" 버튼이 남음. 오류가 나면 다시 생성 버튼도 사라짐.
- 확장을 다시 불러온 뒤 `saveSetting` 등에서 "Extension context invalidated" 예외가 나고 안내가 없음.
- 논문 정보가 여러 탭 사이에서 마지막 저장만 남음: `storage.onChanged` 수신이 없음.
- `L42` 링크·점검 목록의 줄 번호가 이전 문서 기준이라 문서가 바뀌면 어긋남.
- 성능 문제 세 가지.
  - 5초마다 문서 전체를 postMessage로 복사함.
  - 스트리밍 텍스트 영역 갱신 비용이 길이의 제곱으로 늘어남.
  - 기록이 실행마다 문서 전체를 보관함(최대 수십 MB).
- 사용자 프리셋 ID가 줄 번호라, 줄을 끼워 넣으면 빠른 실행이 다른 프리셋을 가리킴.
- 호스트 쪽 결함 네 가지.
  - 마지막 줄에 줄바꿈이 없는 `result` 이벤트를 버림.
  - 출력 줄이 `null`이면 호스트가 종료됨.
  - 웹 다중 턴의 텍스트가 구분자 없이 이어 붙음.
  - 남은 `killTimer`가 다음 실행을 죽일 수 있음(현재 구조에서는 도달 불가).
- 설치 스크립트 문제 세 가지.
  - `$SHELL -lic`가 rc 파일의 입력 대기에 걸리면 출력 없이 멈춤.
  - nvm·asdf 경로가 사라지면 호스트가 실행되지 않음.
  - Linux의 Chrome Dev/Unstable·Snap·Flatpak과 macOS의 Chrome Dev를 지원하지 않음. 제거할 때 TMPDIR 잔여물이 남음.
- 환경 문제 두 가지.
  - `ANTHROPIC_API_KEY`가 환경에 있으면 구독이 아니라 API 과금으로 바뀔 수 있음(❔).
  - 시스템 프롬프트가 명령 인자로 넘어가 Linux에서 다른 사용자가 `ps`로 볼 수 있음.
- 페이지 스크립트가 `olai:mw->cs` 응답을 먼저 보내 문맥을 위조할 수 있음. 페이지가 이미 문서를 갖고 있어 영향은 제한적이지만 README 표현을 고쳐야 함.
- 단축키: macOS에서 `Alt+Shift+A/I`가 모든 페이지의 `Å`·`ˆ` 입력을 막음.

## C. 부족한 기능 명세 (실사용 기준)

우선순위: **P0** 다음 버전 필수 · **P1** 중요 · **P2** 있으면 좋음.

### C1. 다중 파일 프로젝트 지원 — P0
대부분의 논문은 `main.tex` + `sections/*.tex` + `refs.bib`로 나뉜다. 지금은 열린 파일만 보기 때문에 아래가 모두 틀리거나 불가능하다.
- 프리앰블이 다른 파일에 있어 "필요한 패키지"가 늘 "프리앰블 없음"으로 나옴
- 용어 통일·로컬 점검의 라벨/참조 검사가 파일 단위라 오탐이 남(다른 파일의 `\label`)
- 논문 전체를 보는 리뷰어 시뮬레이션·초록·제목 생성이 불가능

**명세**
- 프로젝트 지도: 파일 트리의 문서 ID 목록과 `\input`/`\include` 그래프로 루트 파일을 찾고 읽는 순서를 정한다.
- 읽기: `/Project/<id>/doc/<docId>/download`로 필요한 파일만 가져와 캐시하고, `doc:changed`/`doc:saved` 이벤트로 갱신한다.
- 범위 선택에 **"프로젝트 전체"**를 추가한다. 프롬프트에는 파일 경로별로 `<file path="sections/intro.tex">` 형태로 넣는다.
- 라벨·인용·패키지·용어 분석을 프로젝트 기준으로 한다. 패키지 추가는 루트 파일 프리앰블에 하되, 열린 파일이 아니면 해당 파일을 열어 적용하거나 복사를 제안한다.
- 쓰기는 지금처럼 열린 파일에만 한다(안전).

### C2. 참고문헌(.bib) 연동 — P0
- `\cite{key}` 키 검증: `.bib`에 없는 키, 쓰이지 않는 항목, 중복 항목(같은 DOI·제목)을 찾는다.
- "관련 문헌 찾기" 결과를 바로 쓸 수 있게 한다: 같은 논문이 이미 `.bib`에 있으면 그 키를 쓰고, 없으면 BibTeX를 `.bib`에 추가하고 커서 위치에 `\cite{key}`를 넣는다.
- "인용 필요 위치"에서 기존 `.bib` 항목 중 맞는 것을 먼저 추천한다(웹 검색 전에).
- 참고문헌 검증 결과로 `.bib` 항목을 고칠 수 있게 한다(diff로 확인 후 적용).

### C3. AI 출력 안전 검사(적용 전) — P0
모든 교체·삽입 결과를 적용하기 전에 로컬에서 자동으로 검사한다.
- **보존 검사**: 원문의 `\cite{}`·`\ref{}`·`\label{}`·수식·`%` 주석·사용자 매크로가 결과에서 빠지거나 바뀌면 경고한다. 다듬기 중에 인용이 사라지는 일이 흔하다.
- **환각 수치 검사**: 결과에 원문과 문맥에 없던 숫자, 퍼센트, 연도, 새 `\cite`가 나타나면 강조한다.
- **LaTeX 유효성**: 중괄호와 환경 짝, 이스케이프 안 된 `% & _ #`를 검사한다.
- 결과 영역에 "⚠ 인용 1개 삭제됨" 같은 배지를 보이고, 위험하면 적용 버튼에서 확인을 한 번 더 받는다.

### C4. 문서 전체 교정 모드(인라인 제안) — P1
- 파일 전체를 한 번에 다시 쓰는 대신 **문단 단위로 나눠** 처리하고, 결과를 제안 목록(문단별 diff)으로 보여 준다.
- 제안마다 수락·거절·건너뛰기를 고르고, 진행률과 중단을 지원한다.
- 장기적으로는 에디터에 밑줄로 표시한다(Writefull·Grammarly 방식, CodeMirror 장식 사용).

### C5. 결과 이어서 다듬기(대화형 수정) — P1
- 결과 아래에 "더 짧게", "더 공식적으로", "두 번째 문장 유지" 같은 후속 지시 입력칸을 둔다.
- 직전 결과를 대상으로 다시 실행하고, 원문과 diff를 계속 유지한다.
- 질문·분석 결과에도 후속 질문을 할 수 있게 한다(대화 맥락 유지).

### C6. 빠른 접근 UI — P1
- **선택 영역 말풍선 툴바**: 텍스트를 선택하면 작은 ✦ 버튼이 뜨고, 자주 쓰는 기능 4~6개와 "더 보기"를 보여 준다.
- **우클릭 메뉴**(`chrome.contextMenus`): 선택한 텍스트에 "AI: 다듬기 / 번역 / 질문".
- **명령 팔레트**(`⌘K`): 패널을 열지 않고 기능을 검색해 실행한다.
- 자주 쓰는 기능 고정과 순서 변경.

### C7. 분량·제출 요건 관리 — P1
- 섹션별 단어 수와 목표(예: 초록 250, 본문 8페이지 근사치), 넘친 부분을 표시한다.
- "N단어 줄이기" 목표 기반 간결화: 섹션에 목표 단어 수를 정하면 문단별 축약 제안을 만든다.
- **익명화 점검(로컬)**: 저자명·소속·`\thanks`·"our previous work [X]"·GitHub/개인 URL·감사의 글을 찾는다.
- 학회별 체크리스트 프리셋(NeurIPS checklist, ACL Limitations 필수 등)을 둔다.

### C8. 공동 작업 — P1
- **논문 정보·용어집을 프로젝트 안에 저장**(예: `overleaf-ai.json` 또는 main.tex의 `% overleaf-ai:` 주석 블록)해 공동 저자와 공유한다. 지금은 각자의 브라우저에만 있다.
- AI 수정 기록을 프로젝트별로 영구 보관하고 내보낼 수 있게 한다(지금은 탭을 닫으면 사라짐).
- **AI 사용 공개 문구** 생성: 투고처 규정에 맞춘 Acknowledgments/AI disclosure 문단(Paperpal 대응).
- 변경 추적 모드에서 AI 편집임을 구분할 수 있게, 적용과 동시에 Overleaf 댓글을 다는 옵션.

### C9. 한국어 원고 지원 — P1
- 한국어 맞춤법·띄어쓰기 교정 프리셋(학위논문·KCI용).
- 한영 용어 대응표(용어집에 "한국어 ↔ 영어" 열)와 번역할 때 강제 적용.
- 학위논문 문체(`~이다` 체) 통일 점검.

### C10. 수식·기호 관리 — P2
- **기호 표 생성**: 문서의 수식 기호와 정의 위치를 뽑아 Notation 표를 만들고, 정의 전에 쓰였거나 두 번 정의된 기호를 경고한다.
- 약어 목록(Abbreviations) 생성, 수식 번호 참조 점검.

### C11. 설치·배포 — P0 (사용자 확대의 전제)
- **Windows 지원**: PowerShell 설치 스크립트와 레지스트리(`HKCU\Software\Google\Chrome\NativeMessagingHosts\…`) 등록. 많은 연구자가 Windows를 쓴다.
- 한 줄 설치(`curl … | bash`)와 Homebrew Cask, 확장 zip을 릴리스로 배포한다.
- 패널 안 **진단 마법사**: 브리지 → CLI → 로그인(`claude auth status`) → 테스트 호출을 단계별로 확인하고 고치는 방법을 안내한다.
- 브리지 자동 업데이트 안내(A3-11과 연계).
- 자체 설치형 Overleaf(Community/Server Pro, 기관 도메인) 지원: 선택 권한(optional host permissions)으로 도메인을 추가한다.

### C12. 비용·사용량·개인정보 통제 — P1
- 오늘 사용량(요청 수, 추정 비용)과 자동완성 일일 상한.
- 프로젝트별 AI 끄기, 웹 검색 끄기. 파일 전체 전송 전 확인(설정 가능).
- 작업별 모델 기본값: 예를 들어 교정은 Sonnet, 검토는 Opus, 자동완성은 Haiku.
- 과부하나 사용량 초과 오류 시 대체 모델로 다시 시도(`--fallback-model`).

### C13. 이미지·그림 — P2
- 그림(PNG/PDF) → 캡션 초안, 손글씨 수식·표 사진 → LaTeX(Overleaf·Prism 대응). 이미지를 임시 파일로 넘기는 경로와 권한 설계가 필요하다.

### C14. 테스트·품질 인프라 — P1
- **Overleaf Community Edition(도커)으로 실제 Overleaf에서 E2E**: 진짜 파일 트리, 로그 패널, 자동완성 팝업, 변경 추적, 읽기 전용 사용자를 검증한다.
- 회귀 말뭉치: 실제 논문 형식의 LaTeX 표본(arXiv 소스 등)으로 점검·용어·패키지의 오탐률을 측정한다.
- 성능 예산: 500 KB 문서에서 점검 50 ms 이하, 정규식 시간 상한 테스트.
